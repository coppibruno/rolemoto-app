# SPEC 012 — PWA instalável (sem loja)

> **Status:** Proposta  
> **Autor:** Assistente IA  
> **Data:** 2026-09-09  
> **Referência visual:** `designs/login/` (espaço de badge PWA) + design system cockpit (`globals.css`)  
> **Padrões:** Next.js 15 App Router — Server Components por padrão, Client só com interatividade  
> **Depende de:** SPEC 001 (shell + safe-area do dock), SPEC 002 (`/perfil` + `BotaoSair`), tela de login existente  
> **Não depende de:** backend novo — sem endpoint, sem coleção Firestore

---

## 1. Objetivo

Transformar o Rolemoto em **PWA instalável** no Android (Chrome) e no iOS (Safari), sem Play Store nem App Store.

O piloto abre o site no celular, adiciona à tela inicial e o app abre em **standalone** (sem barra de URL). A distribuição continua sendo **link + “adicionar à tela inicial”**.

Hoje o README e o design system falam em PWA, mas o app **não é instalável**: não há `manifest`, service worker, `theme-color` nem ícones de home. O que já ajuda e **permanece**:

- Viewport com `viewportFit: "cover"` e `userScalable: false` em `src/app/layout.tsx`
- Safe-area no dock, login, perfil, feed e criar-rolê
- Shell mobile-first (`max-width: 560px`) em `src/app/(app)/app.module.css`

Esta spec é **só front + metadados + service worker de shell**. Sem Cloud Function nova.

| Camada | Responsabilidade |
|--------|------------------|
| Front (Next.js) | Manifest, ícones, theme-color, prompt de instalar (login + perfil), página `/offline`, Google via redirect no iPhone |
| Service worker | Cache de assets/shell; **não** cachear API, feed nem perfil |
| Back (Functions) | Sem mudança |

## 2. Referência de Design

Não há mock Stitch de “tela PWA”. O ganho de parecer app vem do **chrome do navegador sumir**, não de telas novas.

Reusar tokens de `DESIGN.md` / `globals.css`. Copy direta: **Adicionar à tela inicial** — nunca “baixe na loja”.

### O que entra nesta spec

- Manifest (`src/app/manifest.ts`): nome, ícones, `display: standalone`, cores `#121316`.
- Ícones 192, 512, **maskable** (Android) e `apple-touch-icon` (iOS), a partir de `public/logo-rolemoto.png`.
- Metas no root layout: `themeColor`, `appleWebApp` (status bar escura).
- Service worker com **Serwist** (`@serwist/next`): só shell/assets.
- Página `/offline`: estado honesto de “precisa de internet” + CTA tentar de novo. Sem dock.
- **Login:** badge + CTA de instalar (o HTML de `designs/login/` reserva esse espaço abaixo do card).
- **Perfil:** item permanente **Adicionar à tela inicial**, acima de Sair / Excluir.
- Android: `beforeinstallprompt` no toque do CTA.
- iOS: sheet com os 3 toques reais do Safari (Compartilhar → Adicionar à Tela de Início).
- Esconder CTA no login se já estiver em `display-mode: standalone` ou se o piloto dispensou (`localStorage`).
- No perfil, o item some **somente** quando já está standalone.
- Shortcut do manifest: Criar rolê → `/criar-role`.
- Login Google no PWA do iPhone: `signInWithRedirect` + `getRedirectResult` (hoje `signInWithPopup` quebra em standalone).

### O que o mock / o produto sugere e **não** entra

| Elemento | Motivo |
|----------|--------|
| Badge “offline-first” no login do Stitch | Mentira: o feed precisa de API + GPS |
| Banner no feed | Combinado: só login + perfil |
| Push / sino de notificações | iOS só depois de instalado; spec futura |
| Cache do feed / mapa offline | GPS velho é pior que tela vazia |
| TWA, Capacitor, Play/App Store | Sem condição de loja nesta fase |
| Splash artesanal por tamanho de iPhone | Android usa ícone + `background_color`; iOS fica com o tema escuro |

### Comportamento visual

- CTA no login: botão secundário (fundo `--surface-container-high`, texto `--on-surface`), ícone `install_mobile` ou `add_to_home_screen`, altura ≥ `touch-min` (48px). Badge pequeno acima ou ao lado: “Instalável no celular”.
- Sheet iOS: overlay + cartão cockpit (`--surface-container-low`, borda laranja sutil), 3 passos numerados, botão **Entendi**.
- Item no perfil: mesmo peso visual de **Sair da conta** (largura total, `label-md` uppercase, ícone à esquerda), cor `--on-surface` — **não** é destrutivo.
- `/offline`: canvas `--surface`, ícone `wifi_off` em `--outline`, título Barlow Condensed, corpo Plus Jakarta Sans, CTA primário **Tentar de novo** (`location.reload()`). Coluna única, gutter 16px, max-width 560px, `pt-safe` / `pb-safe`. Sem `MenuInferior`.

## 3. Fluxo do Usuário

```
Piloto abre o site no celular (HTTPS)
  │
  ├── Ainda no navegador
  │     │
  │     ├── /login
  │     │     ├── Já standalone ou dispensou → sem CTA
  │     │     └── Senão → badge + “Adicionar à tela inicial”
  │     │           ├── Android (evento beforeinstallprompt) → prompt nativo
  │     │           └── iOS / sem evento → sheet dos 3 toques
  │     │
  │     └── /perfil (já autenticado)
  │           ├── Já standalone → item oculto
  │           └── Senão → “Adicionar à tela inicial” (mesmo fluxo Android/iOS)
  │
  └── Depois de instalar
        │
        ├── Abre pelo ícone → standalone (sem URL bar)
        ├── Status bar / notch na cor #121316
        ├── Longo toque no ícone → atalho “Criar rolê”
        ├── Google no iPhone → redirect (não popup)
        └── Sem rede → /offline (shell do SW), não erro genérico do Chrome
```

- Dispensar no login grava `localStorage` (`rolemoto.pwa.ctaDispensado = "1"`). O item do **perfil permanece** — é o lugar permanente.
- Já instalado (`display-mode: standalone` ou `navigator.standalone` no iOS): nenhum CTA de instalar.
- Email/senha **não muda**. Só o Google troca de estratégia no iPhone / standalone.

## 4. Arquitetura Next.js

Seguir a skill: layout/page orquestram, componentes ~80 linhas, lógica no hook, `"use client"` só no que lê `window` / eventos do browser.

O manifest e a página `/offline` são Server. O prompt de instalar é Client.

### 4.1 Por que Serwist (não `next-pwa`)

`next-pwa` está parado e briga com Next 15 / Turbopack. **Serwist** (`@serwist/next`) é o sucessor do Workbox para App Router: gera o SW no `next build` e registra no client.

Escopo do SW nesta spec: **precache do shell** (HTML de `/offline`, JS/CSS estáticos, ícones, logo). Runtime: network-first para navegações; se falhar → `/offline`. **Não** interceptar:

- `https://*.cloudfunctions.net` / emulator de Functions
- Firestore, Auth, Storage
- Rotas de dados do app (`/roles`, `/perfil`, etc. via `api()`)

### 4.2 Estrutura (acréscimos)


### 4.3 Responsabilidades

| Peça | Tipo | Faz |
|------|------|-----|
| `manifest.ts` | Server | Exporta o `MetadataRoute.Manifest` |
| `layout.tsx` | Server | `themeColor`, `appleWebApp`, `icons` |
| `TelaOffline` | Client só se o reload for `onClick`; senão Server + `<a href="/">` | Copy + CTA |
| `useInstalacaoPwa` | Hook | `podeInstalar`, `eIos`, `eStandalone`, `instalar()`, `dispensar()` |
| `CtaInstalarApp` | Client | Badge + botão no login; abre prompt ou sheet |
| `SheetInstalarIos` | Client | Diálogo dos 3 passos; sem `fetch` |
| `BotaoInstalarApp` | Client | Item do perfil; reusa o mesmo hook |
| `loginComGoogle` | Lib | Escolhe popup ou redirect |
| `AuthProvider` | Client | `getRedirectResult` uma vez no mount |

**Não misturar** no mesmo arquivo: markup do sheet + `beforeinstallprompt` + `signInWithRedirect`.

### 4.4 Detecção (contrato do hook)

```ts
// src/hooks/useInstalacaoPwa.ts
const CHAVE_DISPENSADO = "rolemoto.pwa.ctaDispensado";

type EstadoInstalacao = {
  eStandalone: boolean;
  eIos: boolean;
  podePromptNativo: boolean; // tem beforeinstallprompt guardado
  mostrarCtaLogin: boolean;  // !standalone && !dispensado
  mostrarItemPerfil: boolean; // !standalone
  instalar: () => Promise<void>;
  dispensar: () => void;
};
```

- `eStandalone`: `window.matchMedia("(display-mode: standalone)").matches` **ou** `(navigator as Navigator & { standalone?: boolean }).standalone === true`.
- `eIos`: iPhone/iPad/iPod no UA, ou iPadOS com `navigator.maxTouchPoints > 1` e “Mac” no UA (iPad desktop-mode).
- `instalar()`: se houver evento nativo → `prompt()`; senão se iOS → abre sheet; senão (desktop Chrome sem evento) → não faz nada visível além de esconder o CTA.
- `dispensar()` só afeta o CTA do **login**.

## 6. Implementação Front

### 6.1 Login — onde entra o CTA

Abaixo do card (depois do `BotaoGoogle`), **fora** do formulário:

```tsx
<CtaInstalarApp />
```

`CtaInstalarApp` some quando `!mostrarCtaLogin`. Dispensar: link texto “Agora não” (não é o CTA primário da tela — o primário continua **Acelerar / Entrar**).

Não alterar `FormularioLogin` nem `BotaoGoogle`.

### 6.2 Perfil — onde entra o item

Em `FormularioPerfil`, nas ações, **acima** de Sair / Excluir:

```tsx
<div className={styles.acoes}>
  {/* Salvar — já existe */}
  <BotaoInstalarApp />
  <BotaoSair desabilitado={form.salvando} />
  <BotaoExcluirConta desabilitado={form.salvando} />
</div>
```

`type="button"` — não submete o form de edição. Some se `!mostrarItemPerfil`.

Não alterar `BotaoSair`, `BotaoExcluirConta` nem o `PUT /perfil`.

### 6.3 Sheet iOS

Overlay + cartão, `role="dialog"`, `aria-modal="true"`. Passos:

1. Toque em **Compartilhar** (ícone quadrado com seta para cima) na barra do Safari.
2. Role e toque em **Adicionar à Tela de Início**.
3. Confirme **Adicionar**.

Esc / overlay / **Entendi** fecha. Sem `beforeinstallprompt` no iOS — o sheet **ensina**, não instala sozinho.

Reusar o padrão de foco de modal já extraído (`useFocoModal`) se o sheet for modal de verdade. Se for um card simples abaixo do CTA no login, trap de foco é opcional — no perfil, preferir modal (a tela é longa).

### 6.4 Página `/offline`

Rota pública, **fora** de `(app)` — sem `GuardaApp` e sem dock. Se o piloto estiver logado e a rede voltar, “Tentar de novo” recarrega a última URL (o SW deve fazer fallback de navegação para `/offline` e o CTA usa `window.location.reload()` ou `href` da rota que falhou).

Copy:

- Título: **Sem conexão**
- Corpo: **Os rolês precisam de internet.** Filtros, mapa e o login não funcionam offline.
- CTA: **Tentar de novo**

Sem listagem cacheada. Sem “últimos rolês vistos”.

### 6.5 Safe-area (auditoria)

O dock já usa `env(safe-area-inset-bottom)`. Com `black-translucent` no iOS, o notch come o topo se a tela não tiver `padding-top`.

Já cobertos: login, primeiro-acesso, feed, perfil, criar-rolê.

Auditar e corrigir se faltar `padding-top: env(safe-area-inset-top, 0px)` em:

- `src/app/(app)/aprovacoes/`
- `src/app/(app)/roles/[id]/feedback/`
- `src/app/(app)/roles/[id]/participar/` (já usa o inset no cálculo do sheet — conferir o header)
- `src/app/offline/`

Não redesenhar essas telas. Só o inset do topo.

### 6.6 Acessibilidade

- CTAs: `type="button"`, área ≥ 48×48px.
- Sheet: `role="dialog"`, `aria-labelledby`, Esc fecha.
- Não depender só da cor no badge.
- `/offline`: um `h1`, CTA com texto visível (não só ícone).
- `userScalable: false` mantido (ver §5.1).

## 7. Auth no iPhone instalado

Sem isto o PWA iOS “instala e o Google quebra”: `signInWithPopup` não sobrevive ao standalone do Safari.

### 7.1 Regra

| Contexto | Google |
|----------|--------|
| iOS (Safari ou standalone) | `signInWithRedirect` |
| `display-mode: standalone` em qualquer OS | `signInWithRedirect` |
| Demais (desktop, Chrome Android no browser) | `signInWithPopup` (atual) |

Email/senha: inalterado (`signInWithEmailAndPassword` / `createUserWithEmailAndPassword`).

### 7.2 `src/lib/auth.ts`

```ts
const deveUsarRedirect = () => {
  if (typeof window === "undefined") return false;
  const standalone =
    window.matchMedia("(display-mode: standalone)").matches ||
    (navigator as Navigator & { standalone?: boolean }).standalone === true;
  const ios = /iPad|iPhone|iPod/.test(navigator.userAgent);
  return standalone || ios;
};

export const loginComGoogle = async () => {
  if (deveUsarRedirect()) {
    await signInWithRedirect(auth, googleProvider);
    return;
  }
  const resultado = await signInWithPopup(auth, googleProvider);
  return resultado.user;
};
```

`signInWithRedirect` não resolve com `User` na mesma tick — o retorno vem no próximo load.

### 7.3 `AuthProvider`

No mount, **antes** ou junto do `onAuthStateChanged`:

```ts
await getRedirectResult(auth);
```

Erro de redirect (popup bloqueado, conta cancelada) **não** quebra o boot: logar em `console.error` e seguir com `loading = false`. Não mostrar toast no provider — o login já tem faixa de erro se `loginComGoogle()` rejeitar.

`authorizedDomain` do Firebase precisa incluir o host de produção HTTPS. Fora desta spec configurar o console; a spec só exige o código de redirect.

## 8. Service worker (Serwist)

### 8.1 Integração

- Dependência: `@serwist/next` (e `serwist` se o wrapper pedir).
- `next.config.ts`: wrapper `withSerwist` apontando para `src/app/sw.ts` (ou o path que o pacote documentar na versão instalada).
- Registro só em **produção** (`next start` / deploy). Em `next dev` o SW costuma atrapalhar HMR — deixar desligado no dev, documentar no README.

### 8.2 Estratégia

```
Precache: /offline, ícones, logo, chunks estáticos do build
Navegação (document): network-first → fallback /offline
Assets same-origin (script, style, font, image): stale-while-revalidate
Cross-origin / API / Firebase: network-only (não interceptar)
```

Não versionar cache “na mão” além do que o Serwist gera no build.

### 8.3 Pré-requisito de deploy (fora do código, mas bloqueia o aceite no celular)

PWA exige **HTTPS** no mesmo origin do SW. `firebase.json` **ainda não tem Hosting**. Emulator (`localhost`) não prova instalação no iPhone.

Antes do aceite em device real: URL pública HTTPS (Firebase Hosting, App Hosting ou Vercel). Esta spec **não** configura o Hosting — só anota o pré-requisito.

## 11. Critérios de Aceite

### Instalação

- [ ] `GET /manifest.webmanifest` (ou o path que o Next 15 gerar) devolve nome, ícones, `display: standalone`, cores `#121316`, shortcut `/criar-role`.
- [ ] Ícones 192, 512, maskable e `apple-touch-icon` existem em `public/icons/`.
- [ ] Chrome Android: Lighthouse / DevTools marca o app como instalável (manifest + SW + ícone + HTTPS).
- [ ] Após instalar no Android, o ícone abre em standalone (sem barra de URL).
- [ ] iOS Safari: “Adicionar à Tela de Início” usa o `apple-touch-icon` e abre sem chrome.
- [ ] Status bar / theme-color `#121316` (notch não fica branco).

### UX de instalar

- [ ] `/login` mostra badge + CTA se **não** estiver standalone e **não** tiver dispensado.
- [ ] “Agora não” esconde o CTA do login (persiste em `localStorage`) e **não** esconde o item do perfil.
- [ ] `/perfil` mostra **Adicionar à tela inicial** acima de Sair, e some em standalone.
- [ ] Android com evento nativo: o toque no CTA abre o prompt do Chrome (não um sheet falso).
- [ ] iOS: o toque abre o sheet dos 3 passos; não promete instalação automática.
- [ ] Copy sem “loja” / “baixar o app”.
- [ ] Trigger do perfil é `type="button"` (não submete o form).

### Offline e SW

- [ ] SW **não** registra no `next dev` (ou fica claramente no-op).
- [ ] Em produção, sem rede, navegação cai em `/offline` com o copy desta spec — não a dino page do Chrome.
- [ ] `/offline` não tem dock; CTA recarrega.
- [ ] Requests à API / Firebase **não** são servidos de cache stale.

### Auth

- [ ] Email/senha igual ao atual.
- [ ] Google em iOS ou standalone usa redirect; no Chrome desktop/Android browser continua popup.
- [ ] Depois do redirect, a sessão entra (GuardaApp → `/` ou `/primeiro-acesso`) — `getRedirectResult` no boot.
- [ ] Cancelar o Google no redirect não deixa a tela de login travada em loading infinito.

### Qualidade

- [ ] `page.tsx` de `/offline` orquestra; Client só no que clica / lê `window`.
- [ ] Componentes < ~80 linhas; lógica de install no hook; auth redirect em `auth.ts`.
- [ ] Sem `httpsCallable`. Sem endpoint novo.
